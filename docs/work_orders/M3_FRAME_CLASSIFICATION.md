The 104 Frame entries now identify their actual playbook, Class and category:
9 playbook headings, 30 base rules, 52 playbook Requisitions and 13 Class

Requisitions below them on PDF 66, 69, 72, 79, 82 and 85. For example, Nanobot

Requisitions. Classification supplies no mechanical effect by itself.

Project Ankou's heading was incorrectly marked as a mechanic. The Prince was
already correct; the initial hypothesis naming Prince was corrected by checking
the exact registry kinds. Class Requisitions on PDF 92–94 / printed pp.90–92
were also incorrectly grouped under Red Queen. They now have canonical
`frame.class.<class>.<rule>` IDs. All 13 old IDs remain unambiguous aliases, so
references retain their actual source without duplicate rules. Aliases never
bypass module/implementation/review gates. Ambiguous aliases and contradictory
category/Class metadata are rejected.

Ability Unlock/Grafting consumers must use actual category, playbook/Class and
implemented runtime availability. A title cannot grant another Frame playbook
as an extra ability; compulsory packages explicitly reject that category. Class
acquisition, associated runtime effects and normal Permission pricing remain
required M3 work.

New registry fields are additive. Old records load with absent classification,
which invents no eligibility. Registry digest changes still require an actual
matching reviewed scoped approval; no live policy is rewritten. Original planning
files, live database and frozen bot remain unchanged. Acceptance covers all nine
headings, exact Class groups, mixed-page boundaries, alias collisions/history,
legacy metadata absence and replacement package kinds.
