# Reviewed worldbuilding into connected testing

Owner requests implementing the proposed worldbuilding workflow through testing.
Engine-first, synthetic only; no paid provider API, real campaign writes/capture,
Activity installation, deployment or bot operations.

Normal flow: GM opens a source-bound world packet, proposes a typed development
with causal references and current fictional placement, reviews continuity and
permitted effects, then the actual native world authority confirms. Canonical
state/history is updated through a narrow native operation. Explicit later
disclosure teaches selected current actors; hidden goals remain GM-only. A new
hook can prompt a Play or a controller response without resolving either by prose.

Bounded first consumers: introduce an ordinary self-controlled NPC or faction
through existing native services; establish a setting detail, NPC/faction goal or
unresolved complication attached to a real location/NPC/faction. Retain prior
entries on revision and reject duplicate/conflicting active keys or stale targets.
Complications/goals are narrative records, never damage, resource loss, forced
movement/custody, player feelings, automatic completed objectives or clock ticks.
Those require the existing source-specific native operations. No arbitrary state
patches or unrestricted effects router. Prose semantics still require GM review.

Two bounded workers: one owns native narrative development records/validation and
WorldService consumers/tests; one owns committed-world knowledge/disclosure proof
and projection integration/tests. Root owns provider contracts, private proposal
workflow, session integration, native confirmations, connected trial and review.
Agree exact interfaces before dependent edits; do not change policy/registry
approval, existing choice owners or original planning package. Workers write
focused normal/integrity tests; root consolidates pytest after integration.

Completion: synthetic reviewed proposals become actual canonical additions,
private/selected disclosures respect role knowledge, stale/wrong-owner/unsupported
effects fail, retries persist without duplicate state changes, and a connected
scene uses the additions in Handler guidance and actual Play/controller workflows.
Run focused checks and a small independent interpretation audit if useful. Update
the consolidated Activity handoff with exact APIs and remaining semantic limits.
