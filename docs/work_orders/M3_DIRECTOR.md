# M3G — Director presence and Handler rule context

Status: IN_PROGRESS / RULES_SUBSET. Book PDF 192 / printed p.190 defines the
Director's rules. PDF 151 / printed p.149 explicitly requires another player for
High Budget 1/1. Applying separate control to every Director scene is the recorded
campaign recommendation, rather than a universal restriction in generic NPC rules.

Actual NPC introduction/role acceptance and actual appearance remain separate.
Arrival creates a source-bound presence review for the current Handler. The Handler
records its own actual presence and chooses two ordinary Identity names. Starting a
new continuous presence sets Heat to zero; overlapping Directors share the existing
context. This is a context for the actual Handler, without a copied Pilot sheet,
Frame, creation choices, Cadre rank or mission participation. Identities/marks and
source work remain stable. A completed actual scene with the Director and without
the Handler can instead prove absence; no client boolean waives an unknown effect.

The Handler's ordinary rule authority is blocked while an actual context is active.
Own scene attestations remain possible through a narrow authority path that does
not perform Handler Plays or award resources. Only each actual NPC controller
records its own Director's departure. The last departure closes the context with
no free Heat, unmark or restoration of an earlier balance. Context/receipt history
is retained; a new presence needs a new source event. All of these are atomic,
versioned, private, pause-aware and owner-bound. Native requests expose the review,
private Handler resources and separately controlled departure.

Still required: shared Girl Play ports for the Handler context; Director Handler
Plays and owned prices, phone-call/Strain rules, death/replacement, world reprimand
and firing consequences, NPC-controller changes and full role/cast integration.
Presence absence outside the completed Observation-scene proof needs a broader
actual cast/response workflow. The High Budget 1/1 extra four Heat must be applied
after its actual initial context, once that table branch has its typed resolver.
Unsupported actions remain gated; a context setup is not complete Director rules.

Acceptance includes exactly two owned starting choices, actual zero-Heat start,
no Pilot/rank fabrication, no repeated baseline grant, continuous overlap, actual
scene absence proof, each Director's own departure, retained cards/marks/Heat,
stale/current principals, policy/revision checks, source provenance, private views,
rollback, concurrent/replayed submissions, safety, native controls and rebuild.
Independent review, human testing and live activation remain pending.
